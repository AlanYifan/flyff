# FlyFF 数据更新器（ApiUpdater.vue）

## 功能概述

FlyFF 数据更新器是一个可视化操作页面，用于从 flyff.com 官方 API 拉取最新游戏数据与图标资源，并写入项目文件。该组件融合了原 `get_Flyff_API.html` 的全部功能，提供友好的图形界面替代手动脚本操作。

### 核心能力

1. **一键增量更新**：自动比对版本号 → 检测缺失 ID → 增量拉取详情 → 写入 `src/data/` 数据文件 → 下载缺失图片到 `public/pt/`
2. **断点续传**：更新任务被中止后，可从断点处继续，跳过版本比对和已完成的类别
3. **失败 ID 重试**：请求失败的 ID 自动汇总，支持一键重试（后端按ID重新拉取详情、写入对应数据文件并补下载缺失图标，真正落地数据）
4. **更新记录查看**：查看历次 API 数据更新的详细记录，包含新增数量、失败数量、图片下载统计等
5. **已有条目 CNS 同步**：检测到版本变化时，对已有条目的 `name.cns` / `description.cns` 逐条与官方比对并更新（套装为每轮逐条比对）
6. **冗余数据检测**：比对时报告「本地有、官方 API 未返回」的条目数量与 ID 列表（冗余数据只报告不删除）
7. **旧版全量更新**：保留的兼容功能，按顺序执行所有 API 数据拉取与图标下载，结果下载到浏览器下载目录

### 支持的数据类别

| 类别     | 数据内容       | 图标下载 | 数据文件（写入）            |
|----------|--------------|---------|---------------------------|
| 物品     | 物品详情       | ✅       | `src/data/ITEM_INFO.js`    |
| 怪物     | 怪物详情       | ✅       | `src/data/MONSTER_INFO.js` |
| 技能     | 技能详情       | ✅       | `src/data/SKILL_INFO.js`   |
| 地图     | 地图详情       | ❌       | `src/data/MAP_INFO.js`     |
| NPC      | NPC 详情      | ✅       | `src/data/NPC_INFO.js`     |

| 装备套装 | 套装属性       | ❌       | `src/data/SQ_SET.js`       |

```
用户点击按钮
    ↓
```

## 页面功能区域

### 1. 后端服务状态

- 位置：页面顶部（操作后显示）
- 显示 Go 后端服务 (localhost:8080) 的连接状态
- 绿色 = 已连接，橙色 = 未启动
- 未启动时提示「请先启动 Go 后端服务（端口 8080）」

### 2. 全局进度条

- 位置：状态栏下方
- 运行中或完成时显示
- 展示当前进度百分比与预估剩余时间

### 3. 输出日志区域

- 位置：进度条下方
- 实时展示操作日志，支持三种状态样式：成功（绿色）、错误（红色）、警告（橙色）

### 4. 版本信息区域

- 本地版本：当前 `src/data/` 中数据对应的版本号
- 远程版本：flyff.com API 返回的最新版本号
- 更新状态：需要更新 / 已是最新 / 未检测

### 5. 一键增量更新区域（主功能）

- 标题右侧显示「服务端」和「网络」状态徽章
- 三种状态颜色：绿色（在线）、红色（离线）、灰色（未检测）
- 操作流程：
  1. 并行检测服务端 + 网络状态
  2. 服务端离线 → 提示错误
  3. 网络不通 → 提示错误
  4. 支持断点续传时显示「继续更新」按钮
- 更新完成后展示三类统计：
  - 📊 数据更新统计（远程/本地/新增/失败）
  - 🖼️ 图片下载统计（共/下载/已存在/失败）
  - 📝 CNS 名称与描述比对统计
- 失败 ID 汇总区域：按物品/怪物/技能/图标分类展示，支持清空和重试

### 6. API 更新记录区域

- 查看历次更新的详细记录
- 每条记录展示：版本变化、时间、各分类新增数量
- 支持分页浏览（每页 20 条）

### 7. 旧版全量更新（折叠区域）

- 兼容保留的旧版功能
- 按固定顺序依次执行 12 个步骤
- 数据保存为 JSON 文件下载到浏览器下载目录
- 步骤列表实时展示进度

## 使用说明

### 前置条件

1. **Go 后端服务**：必须先启动 Go 后端（`server/start.bat` 或 `go run server/main.go`），监听端口 8080
2. **网络连接**：需要能访问 `api.flyff.com`
3. **速率限制**：API 请求限制为 290 次/分钟，前后端均已实现速率控制

### 操作步骤

1. 访问页面：`http://localhost:3000/data-updater`
2. 确认「服务端」和「网络」状态徽章为绿色
3. 点击「🚀 一键更新全部数据」按钮
4. 等待更新完成，查看输出日志和统计数据
5. 如有失败 ID，点击「🔄 重试失败ID」

### 断点续传

- 更新过程中点击「⏹ 中止任务」可随时停止
- 中止后已获取的数据会保存到文件
- 再次点击按钮显示「▶️ 继续更新」，从中断处继续
- 续传按「数据拉取 / 图片下载 / CNS比对」三个阶段分别判断是否完成，任一阶段未完成都会继续执行，已完成的阶段不会重复跑

### ⚠️ dist 部署模式下更新不会立即生效

更新器写入的是**源码数据文件**，客户端在构建期通过静态 `import` 打包读取：

| 运行模式 | 数据写入位置 | 对运行中的客户端是否生效 |
|---------|-------------|----------------------|
| 开发模式（exe 在 `server/`） | `<项目根>/src/data/*.js`、`<项目根>/public/pt/` | ✅ Vite HMR 立即生效 |
| dist 部署模式（exe 在 `dist/`） | `<exe目录>/src/data/*.js`、`<exe目录>/pt/` | ❌ **不生效**，需重新构建后才生效 |

因此 dist 部署环境下，正确流程是：**先执行数据更新 → 再 `npm run build`（重新构建前端）→ 再部署**。单独点「一键更新」不会改变已部署客户端读到的那份数据（`dist/assets/js/item-info-*.js` 等构建产物）。

## 失败 ID 管理机制

1. 请求失败（3 次重试均失败）的 ID 按 `items`/`monster`/`skill`/`image`/`achievement` 分类记录
2. `failedIdsMap` 持久化到 `localStorage`（key: `flyff_api_failed_ids_map`），刷新页面不丢失
3. 支持一键重试（物品/怪物/技能/成就）：调用后端 `POST /api/data/retry-ids`，后端重新拉取详情、写入对应 JS 数据文件并补下载图标；`image` 分类（图标下载失败）保留，由图标下载流程处理
4. 全部成功时自动清空 `failedIdsMap`

## 维护指南

### 修改更新逻辑

- **增量更新流程**：修改 `server/flyff_data_updater.go`，修改后需重新编译（`go build`）
- **前端轮询与展示**：修改 `src/composables/useFlyffApiUpdater.js`
- **UI 布局与样式**：修改 `src/views/ApiUpdater.vue`

### 修改数据类别

1. Go 后端 `flyff_data_updater.go` 中的 `updateCategories` 和 `imageCategories` 数组
2. 对应的数据文件写入逻辑
3. 前端统计展示中的分类名称映射

### 注意事项

- `src/data/` 下的核心静态数据文件禁止直接修改，只能通过 API 更新器写入
- Go 后端修改后必须重新编译才能生效
- 前端轮询间隔为 800ms，不建议过于频繁
- 图标文件下载到 `public/pt/` 对应子目录
